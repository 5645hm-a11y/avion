# Media engine foundation

Layers 0–3 in C++20, including a working Windows H.264 (I/P/B) + AAC-LC MP4 playback demo. The core, demuxer, clock and H.264 syntax parser are portable; IOCP, WASAPI, native Microsoft AAC decoding, D3D12 decode and compute presentation provide the Windows reference backend. No third-party libraries or package downloads. MSVC builds use the static CRT.

Read [the architectural blueprint](architecture.md) for the pipeline, ownership protocol, clock mathematics, GPU synchronization, presentation design, and limits of the guarantees.

Read [Layer 1's design and admission limits](layer1.md) for asynchronous I/O, cross-platform contracts, MP4/fMP4 parsing, zero-copy ownership, and verification.

Read [Layer 2's implementation and limits](layer2.md) for the predictive clock, PCM endpoint, GPU fence/DPB lifetime proof, and hardware verification.

Read [Layer 3's playback design and supported subset](layer3.md) for the H.264 frontend, NV12 shader, native AAC bridge, orchestration, tests and demo commands.

Read [Layer 4's HEVC frontend and verified inter decode](layer4.md) for the H.265 syntax parser, its DXVA adapter, pixel-level hardware verification, and the decoder-backend fix it uncovered.

Read [Layer 5's HEVC playback](layer5.md) for presentation reordering, P010/BT.2020 conversion, the 4K envelope and single-entry edit lists. Its historical HDR-rejection and pause limitations have since been replaced by tone mapping and resilient pause/resume.

Shaky footage holds still: **Alt+S** or "stabilize video" (in nine languages, "ייצב תמונה", "stabiliser la vidéo") steadies the windowed player's view with no IMU, the camera's motion read off the picture's background on the way to each conversion, so the steadied view is reconstructed from the picture's own samples, not enlarged afterwards: [14.73 px rms of jitter on screen to 0.92](picture.md#stabilising-the-window-2026-11-04), a pan passing through, 0 pictures dropped at 4K60 HDR.

Read [the C99 SDK](sdk.md) to embed the engine from C: modules a host can leave out (each an exact arena region and its threads), the wake policy, the per-frame signatures, host-driven playback on every platform (Linux included), and live sensors (API 3): a camera's NV12/P010/RGBA frames (with IMU deltas) and a microphone array pushed in instead of a file, with [perception](picture.md#perception-flow-looming-and-saliency-2026-10-22) read back (per-tile flow, looming with time to contact and the hazard's position, a 16 x 16 foveated saliency grid) and the [audio saccade](audio-dsp.md#sound-localisation-and-the-audio-saccade-2026-10-22) ("look at sound": the view turns toward a sudden sound's direction); with API 4, [the GPU's passes on those frames](sdk.md#gpu-live-ingest-and-stabilisation-2026-10-22-second-directive) (shadow lift and the other picture controls, micro-motion, edge-directed or neural super-resolution, read back as an RGBA image) and [IMU stabilisation](picture.md#stabilisation-2026-10-22); with API 5, [roll stabilisation, micro-motion that follows the stabilised view, and native 10-bit P010 on the GPU](sdk.md#roll-ten-bit-and-compensated-micro-motion-api-5-2026-10-27), and perception's [fovea and ground model](picture.md#the-fovea-and-the-ground-2026-10-27) (a distant obstacle found from 2.8 s of contact on real footage, the ground a camera travels over no longer an approach), since 2026-10-28 [wherever the horizon is and in under 0.5 ms a picture](picture.md#pitch-crops-and-speed-in-perception-2026-10-28) (SSE2 and AVX2, bit-identical to the scalar loop), and since 2026-10-29 [under 0.5 ms on a fully textured picture too, with the surf and reflections no longer approaches](picture.md#the-predicted-search-the-surf-and-the-low-horizon-2026-10-29) (a predicted diamond search; four windows on an object, isotropic, persisting). The windowed engine keeps its window on [a thread of its own](session.md#the-window-thread-2026-10-28) (a stalled message dispatch no longer drops pictures) and [turns the picture](picture.md#rotation-2026-10-28): a file's `tkhd` orientation from its first frame, R and "rotate video" / "סובב תמונה" / "tourner la vidéo" and leveling while playing or paused, and [levels the horizon by itself](picture.md#auto-leveling-the-horizon-2026-10-29) (Shift+R, "auto level", "יישר אופק אוטומטית", "niveler l'horizon"): the conversion's statistics pass histograms the picture's edge orientations on the GPU and only those 1,024 bytes come back (+4.5 and -6.0 degrees found within 0.1); since 2026-10-30 [through black bars encoded in the picture, which X and "crop black bars" / "recadrer les bandes noires" crop away, and not fooled by lines in perspective](picture.md#black-bars-perspective-and-real-footage-2026-10-30) (real footage turned by a known roll: within 0.4 degree). With API 6 the SDK's host mode [turns, levels and crops too](sdk.md#rotation-the-horizon-and-black-bars-api-6-2026-10-30): `media_picture_t` says how to draw the picture, the telemetry has the horizon's tilt and the picture inside the bars, and the GPU image comes back leveled and cropped. Playback [keeps its audio lead](session.md#the-audio-lead-2026-10-30): the worker reads audio past a video packet waiting for a decoder surface, and a short underrun is bridged without stopping the clock (a GPU-bound run: 52 clock re-anchors and 5.3 s of underrun silence before; now no silence, and only the anchors after its four seeks). With API 7 perception [keeps track of several objects at once](picture.md#several-objects-at-once-2026-10-31): up to four approaching or salient objects, the most urgent first (soonest time to contact), each with a track id that stays with it; "next target" / "מטרה הבאה" / "cible suivante" (and Tab while tracking, in the windowed engine) moves the lock, the view and the audio zoom's beam onto the next one, and [the GPU image turns by quarter turns](sdk.md#several-objects-at-once-api-7-2026-10-31). The host's CPU survey of the horizon and the bars is [ten times cheaper](picture.md#the-cpu-survey-2026-10-31) (0.10 ms a 640x480 picture with AVX2, 1.09 before; SSE2, AVX2 and scalar give the same histograms bit for bit). With API 8 [objects keep their ids when they cross](picture.md#objects-that-cross-2026-11-01) (each track's line through its recent centres predicts it; a region two tracks share is split between them; the rest assigned by the least total cost of distance, direction, size, shape and brightness; one hidden behind another stays in the table), Tab works [the very next picture after T](picture.md#objects-that-cross-2026-11-01) (the object table is kept warm), the GPU image can [fit a 90-degree turn whole between black bars](sdk.md#fit-instead-of-fill-api-8-2026-11-01) (`MEDIA_SENSOR_GPU_FIT`), and S, "take snapshot", "צילום מסך" or `media_engine_save_snapshot` write [a forensic snapshot](picture.md#forensic-snapshots-2026-11-01): the picture as made (zoom, leveling, the picture controls, the split view) as an uncompressed BMP with its telemetry beside it (time, frame hash, view, orientation, horizon, objects and target), on a thread of its own, nothing allocated, no picture dropped. With API 9 the engine [measures vibration and a pulse remotely](picture.md#remote-vibrometry-2026-11-02) (a region held still in the scene against the camera's shake: 72.00 BPM from a ±1.5-code pulse, 8.000 Hz from a ±0.3-sample vibration; the windowed HUD says "Pulse 72 BPM" while tracking or with micro-motion), turns any camera into [a stabilised neuromorphic event camera](picture.md#event-camera-2026-11-02) (ON/OFF events in time order; a shaking, rolling camera over a still scene fires 0.012 % of the events it fires unstabilised), [reads a compressed H.264 or HEVC picture's QP, cost, motion and scene cuts before decoding it](picture.md#bitstream-perception-2026-11-02) (0.1–0.4 µs a picture; the cut found in Microsoft's and Intel's encoders' streams and nowhere else) and [exports the fovea or the view as an NCHW float32/float16 tensor](picture.md#tensor-export-2026-11-02) for a model, in the caller's buffer. With API 10 vibrometry [follows a moving target without restarting its window](picture.md#moving-targets-2026-11-03) (72 BPM over the whole 8.5 s while the target crosses the picture), files and cameras without an IMU are steadied by [a virtual IMU read off the background](picture.md#the-virtual-imu-2026-11-03) (within 0.07 sample of the true shake; the pulse still 72 BPM, the event camera as quiet as with the real IMU), and the windowed player [measures Y', Cb and Cr at full resolution on the GPU](picture.md#vibrometry-in-the-window-2026-11-03) (a pulse in the colour alone, with the brightness still, found in Cr), [runs the event camera and exports tensors](picture.md#the-event-camera-and-tensors-in-the-window-2026-11-03) (identical to host mode's), while the bitstream inspector [keeps every HEVC sequence's reference sets](picture.md#several-sequences-in-one-bitstream-2026-11-03) and 4K60 HDR cold starts [no longer keep the expensive tier while the queue is thin](fixtures.md#cold-starts-the-thin-queue-2026-11-03).

Playback no longer spins a core: [low-power pacing](session.md#low-power-pacing-2026-10-22) puts the presentation thread and the media worker to sleep between pictures (high-resolution waitable timers, the endpoint's period event, the decoder's and the GPU's fences), from about 2 cores to 6-17 % of one while playing and under 2 % while paused, with no picture dropped.

The current renderer also includes PQ/HLG tone mapping, the [glass dock HUD](kinetic-hud.md) (GPU-only SDF geometry: Play/Pause morph, timeline, clocks, pointer and keyboard controls, independent redraws during pause) and [multilingual GPU subtitles](subtitles.md) (SRT/WebVTT shaped once by DirectWrite, including right-to-left and complex scripts, drawn from a paged signed-distance atlas that is filled on demand by a background shaping thread: no glyph limit, no dot substitution and no startup cost; optional and never fatal to playback). The window [resizes, follows per-monitor DPI and toggles borderless fullscreen](resizing.md) without reallocating video resources. Pause/resume and [seeking](seeking.md) are connected to the engine: releasing a timeline drag seeks by epoch-based repositioning (sync-sample lookup, DPB reset, audio flush, clock re-anchor) and lands on the exact target frame, also while paused; audio restarts on the target sample through AAC pre-roll, and scrubbing is coalesced. A seek ahead inside the group of pictures being decoded carries on decoding from where it is instead of restarting from the sync sample ([forward continuation](seeking.md#forward-continuation-2026-10-15): 3 instead of 20 reference pictures, a 4K landing in 38–41 ms instead of 150–163 ms). A seek to a picture already decoded keeps it and decodes nothing again ([queue seek](seeking.md#queue-seek-2026-10-16): landing within one display refresh), and the reference pictures a seek decodes on its way are submitted back to back ([seek catch-up](seeking.md#seek-catch-up-2026-10-16): 720p restart −22 %; 4K is bound by the decode engine's ~6 ms per picture). Dragging the timeline backward previews: a target whose exact frame needs more than two pictures decoded first shows its sync sample alone (4K: 11–15 frames in the backward half of the scripted drag instead of 5–6), marked as a preview on the dock, and the release lands exactly ([scrub preview](seeking.md#scrub-preview-2026-10-16)). Files carry [chapters](chapters.md) (Nero `chpl` or a QuickTime chapter track) or get sections synthesized from their structure (sync-sample cadence and sizes, dialogue gaps), plus scenes from cuts seen while playing; the dock shows them as ticks, and "next chapter", "סצנה קודמת" (nine languages) and Page Down / Page Up move between them. Automated test windows take no desktop input ([test windows](kinetic-hud.md#test-windows-2026-10-16)). [Hardware faults are recovered without stopping playback](recovery.md): a removed D3D12 device is rebuilt in the same epoch with no leaked reference (audio plays on untouched), and an invalidated audio endpoint moves to a replacement, or to a silent null endpoint while none is available, with the media clock kept continuous. The audio fault tests invalidate the stream in-process, so a test run never takes the machine's audio device from other applications; the real exclusive-mode steal runs only on request (`--test-exclusive-steal`, `-DMEDIA_TEST_EXCLUSIVE_STEAL=ON`).

- [`H264SyntaxParser`](../include/media/codec/H264SyntaxParser.hpp) and [`H264Dxva`](../include/media/platform/windows/H264Dxva.hpp): immutable EBSP parsing, bounded SPS/PPS/slice tables, I/P/B slices with list modification and weights, POC types 0/1/2, full reference marking (sliding window, MMCO 1-6, long-term), and native DXVA translation. See [H.264 B-pictures](h264-bframes.md).

- [`NeuralUpscalePass`](../include/media/render/NeuralUpscalePass.hpp) ([neural](neural.md)): a 1,356-parameter micro-ESPCN (5.4 KB of weights in [`NeuralWeights.hpp`](../include/media/render/NeuralWeights.hpp), trained by the deterministic in-repo C++ trainer `tools/train_neural.cpp` on clean and H.264-compressed input from the Windows codec, so it also deblocks and derings) reconstructs 2x luma in one D3D12 compute pass before conversion and tone mapping; residual over bilinear, deringed, flat tiles skipped, and tiles whose 20×20 source neighbourhood still matches the one they were evaluated from not evaluated again ([temporal tile reuse](neural.md#temporal-tile-reuse-2026-10-19): exact matching is bit-identical, about 6× faster on a still 1080p picture; playback matches within one code of compression noise without drift, which reuses 34.8 % of the tiles of a decoded 720p60 stream and lets the network keep up with it). The quality governor turns it on and off; **N** cycles the quality modes. No ML runtime. Held-out photos: 48.49 dB against 47.22 dB bicubic clean, 44.51 against 43.49 dB at H.264 QP 22.
- [`ColorPipeline`](../include/media/render/ColorPipeline.hpp) spatial stage ([picture](picture.md)): edge-directed luma reconstruction while upscaling, luma-guided 4:2:0 chroma (colour edges follow luma edges instead of bleeding; **C** toggles it), and opt-in contrast-adaptive sharpening in linear light, fused into the conversion dispatch; point-load source access makes the base conversion 2.3x faster on the reference GPU. Above 2× downscaling (4K in a 720p window) each output pixel averages its source footprint instead of taking one bilinear sample (aliasing ÷4.8 at 3×), and 10-bit and HDR sources are dithered to 8 bits (banding 0.287 → 0.022 LSB) ([downscale prefilter and dither](picture.md#downscale-prefilter-and-dither-2026-10-16)). Every conversion is exact to the crop (nothing from the coded padding reaches the screen), anamorphic video is shown at its sample aspect ratio (VUI or `pasp`), and the colour description is resolved from the container and the bitstream ([`PictureGeometry`](../include/media/video/PictureGeometry.hpp), [`ColorDescription`](../include/media/video/ColorDescription.hpp)). **V** (or "compare quality", "השווה איכות") splits the picture: the plain conversion on the left, the enhanced one on the right, each bit for bit, with a seam between them ([split comparison](picture.md#original--enhanced-the-split-comparison-2026-10-19)). While paused, **V**, **N** and **C** change the picture on screen at once ([paused re-conversion](picture.md#paused-re-conversion-2026-10-19)).
- [`QualityGovernor`](../include/media/render/QualityGovernor.hpp) ([picture](picture.md#quality-governor-2026-10-15)): in Auto mode (the default) chooses Neural super-resolution, Edge-directed with guided chroma, or Fast bilinear from the p95 of each conversion's GPU time (D3D12 timestamp queries, 32 pictures), with hysteresis, exponential back-off and a memory of what each tier cost, so the presentation queue's work stays inside the frame interval; a status cue for every change. **N** cycles Auto, Neural, Edge-directed and Fast.
- [`D3D12Renderer`](../include/media/render/D3D12Renderer.hpp): borderless window, NV12/P010 conversion and HDR tone mapping, sixteen processed textures, GPU history, procedural glass dock and SDF subtitles, nonblocking flip presentation and reverse surface leases.
- [`SubtitleTrack`](../include/media/subtitle/SubtitleTrack.hpp) and [`SdfSubtitlePipeline`](../include/media/render/SdfSubtitlePipeline.hpp): allocation-free SRT/WebVTT cue selection; DirectWrite shaping with per-line bidi on a background thread, a paged GPU signed-distance glyph atlas (2048 cells as a cache; tracks with more distinct glyphs page through it, every glyph drawn as itself), one instanced draw per active cue. `--subtitles file.srt`. A 92-concept English/Hebrew/Arabic table (28 KB, indexed once), prefix and ending rules per script, per-cue concepts in the arena; a `Concept match: "…"` cue shows the line found.
- [`ResumeLedger` and `Playlist`](../include/media/session/MediaSession.hpp) ([sessions](session.md)): a file opened again resumes where it was left (past 15 s, more than 60 s before the end) with its audio and subtitle tracks and its bookmarks; the last 64 files in a checksummed 19 KB ledger (version 1 ledgers still load). **Ctrl+Right** / **Ctrl+Left**, "next video" or "הסרטון הקודם" play the next or previous file of the folder in natural order, in the same window, passing over files that cannot play. - Zoom ([picture](picture.md#zoom-2026-10-20)): 1× to 8× into any region, reconstructed (edge-directed or neural) from the region's own samples rather than magnified afterwards. **Ctrl + wheel** at the pointer, the arrows pan, "zoom in", "אפס זום". While playing, a change is on screen from the next composite ([live zoom](picture.md#live-zoom-2026-10-21)): the pictures already converted are shown through it (`PictureBlit` samples the new region out of the old one), then native pictures take over.
- A–B loop ([seeking](seeking.md#ab-loop-2026-10-21)): **L** marks A, then B, then clears; "loop this sentence", "לופ על המשפט" loops the cue on screen padded 150 ms. Each turn back to A is judged by the clock (0–0.3 ms past B) and lands exactly on A; the dock draws the loop as a mint bracket. From the second turn on, a loop turns through [pinned pictures and sound](seeking.md#pinned-loop-turnaround-2026-10-21): A's first converted pictures and 500 ms of its PCM are kept from the first pass, so a turn on a long-GOP 4K file lands in **1.1–4.2 ms** instead of 58–70 ms, its sound starting within 0.02 ms of A, with 0 pictures dropped.
- Night mode ([audio](audio-dsp.md#loudness-and-night-mode-2026-10-21)): a BS.1770-4 meter ([`LoudnessMeter`](../include/media/audio/Loudness.hpp): K-weighting, momentary, short-term, gated integrated loudness, 4× true peak) and [`NightMode`](../include/media/audio/Loudness.hpp) (lift up to +12 dB and cut to −12 dB towards −20 LUFS, frozen in silence so no noise floor is raised, a −1 dBTP look-ahead true-peak limiter, 1.44 ms of latency, bit-identical when off). **K**, "night mode", "normalize volume", "מצב לילה", "אזן עוצמת קול"; the telemetry panel shows LUFS and dBTP.
- Bookmarks and Pinned | Live ([session](session.md#bookmarks-2026-10-21), [picture](picture.md#pinned--live-2026-10-21)): **B**, "add bookmark", "סמן הערה" set up to 32 bookmarks a file, kept in the resume ledger and drawn as amber flags on the dock; "go to bookmark 2", "next bookmark", "לך לסימנייה" land exactly on them. **Ctrl+B** or "הקפא פריים להשוואה" pins the frame on screen, and **V** shows it beside the live picture.
- C99 SDK and modules ([SDK](sdk.md)): [`c_api.h`](../include/media/c_api.h) embeds the engine from C (plain structs, one opaque handle in the host's own storage, no heap). Six modules (voice, HUD, subtitles, neural upscaling, chapters, telemetry) can be left out at initialisation: each is a fixed region of the arena and its threads, so leaving one out removes exactly that (`media_query_arena_budget`: 239.1 MiB with all, 192 MiB with none). The wake word can be "Avion", the host's own name, or push-to-talk; a custom name is made hearable at open (formant renditions plus the host's or the system's voices: held-out real voices wake on it 4-6 of 6, with no false wake; see [voice](voice.md#custom-wake-words-2026-10-21)). Every picture on screen comes with a 64-byte frame signature built from what the engine already computed: mean and peak luma, moving blocks, scene cuts, speech probability and the dominant band. `MEDIA_PLAYBACK_HOST` plays on any platform with no thread of its own: the host calls `media_engine_step` and `media_engine_pump_audio` and presents; video through the host's decoder or the engine's software bridge (H.264 I_PCM and skipped macroblocks, bit-exact), PCM tracks (`ipcm`, `fpcm`, `sowt`, `twos`) or the host's audio decoder, the DSP, speed, subtitles, commands and voice all on board (verified end to end on Windows and Linux GCC with ASan/UBSan).
- Target tracking ([picture](picture.md#target-tracking-2026-10-21)): **T** or "track target" / "עקוב אחרי האובייקט" locks onto what is in the middle of the view; a GPU luma-grid pass and a window-weighted ZNCC tracker with an alpha-beta filter move the zoomed view with it (sub-cell matches: 0.17 cells RMS on a synthetic sequence), the audio zoom's beam follows the view on screen, and on occlusion or a cut the view holds with "Tracking lost · Holding view".
- Mastering EQ and audio zoom ([audio](audio-dsp.md#mastering-eq-and-audio-zoom-2026-10-21)): a 10-band EQ (within 0.04 dB of its analytic response, bit-identical when flat) with ISO 226 iso-loudness, speech-protected ducking of the bass under a voice, and a notch killer that finds stationary drones and mains hum by phase-vocoder tracking and notches them at Q 12 (−42 to −49 dB, the voice's spectrum within 0.12 dB). "audio zoom", "זום אקוסטי": the picture's zoom steers a phase-coherent beam toward what is zoomed into (a source on the far side −10.3 dB).
- Picture controls and micro-motion ([picture](picture.md#picture-controls-and-micro-motion-2026-10-21)): brightness, contrast, saturation, gamma and a highlight-safe shadow lift in the conversion dispatch (bit-identical above Y' 0.75); "micro motion", "tactical vision", "הדגש תנועה זעירה" magnify small temporal luma changes ×6 against a per-pixel reference (a ±2-code pulse becomes 14.5 codes) while motion is left alone (a moving edge is bit-identical, no ghost). Symptom cures ("too dark" / "חשוך", "noisy" / "יש זמזום", "muffled" / "הדיבור נבלע") set the remedy, and "undo" / "בטל" puts back exactly what was there ([intents](intents.md#audio-zoom-micro-motion-and-cures-2026-10-21)).
- Flight recorder and telemetry ([session](session.md#flight-recorder-telemetry-readout-and-watchdog-2026-10-21)): two bounded lock-free [`FlightRecorder`](../include/media/core/flight_recorder.hpp)s (256 events each, presentation thread and media worker) keep what the engine did. **I**, "show stats" or "הצג נתונים" shows a glass panel of the engine's own numbers, and "why did quality change?" / "למה האיכות ירדה?" names the tier the governor left and the p95 it measured. A watchdog turns a hang in an automated run into a failure that says where each thread was.
- Music mode ([audio](audio-dsp.md#music-mode-2026-10-20)): an `.m4a` or any file with AAC alone plays with everything the audio path has (clock, DSP, volume, speed, chapters, resume, voice), and the window shows its sound: [`SpectrumAnalyser`](../include/media/audio/SpectrumAnalyser.hpp) (32 log bands, waveform, level, per 1024 frames, stamped in media time) hands its pictures through a lock-free ring to [`VisualPipeline`](../include/media/render/VisualPipeline.hpp), an SDF spectrum ring, orb and waveform ribbon drawn at the display's rate.
- [`CommandPalette`](../include/media/ui/CommandPalette.hpp) and [`PalettePipeline`](../include/media/render/PalettePipeline.hpp): the in-window command bar. **/** (or **Ctrl+F**, **Ctrl+K**) opens it; text in any script, including input-method compositions, is typed into it; **Enter** runs it as a command or searches the subtitles for it; **Escape** dismisses it. See [command bar](command-palette.md).
- [`Win32WasapiCapture`](../include/media/platform/windows/Win32WasapiCapture.hpp) and [`UtteranceBuffer`](../include/media/ai/UtteranceBuffer.hpp): the two ends of the offline voice path. Event-driven WASAPI microphone (or loopback) capture into a bounded lock-free ring of 16 kHz mono PCM, and the fixed buffer that hands a recogniser's words to the command grammar. Between them, [`MicroVad`](../include/media/audio/MicroVad.hpp) finds utterances, [`FilterbankFeatures`](../include/media/audio/FilterbankFeatures.hpp) computes 24-channel log-mel frames, and [`AcousticIntentRecognizer`](../include/media/ai/AcousticIntentRecognizer.hpp) recognises 54 words (31 English, the wake word "Avion", 22 Hebrew, the chapter and scene commands among them since 2026-10-16) alone or as spoken sentences by dynamic time warping against shipped templates (864,488 bytes, packed; about 35 ms a sentence with a pruning beam), each sentence decoded per language with that language's own acceptance. [`AvionWakeGate`](../include/media/ai/AvionWakeGate.hpp) acts only on speech addressed to the player by name: "Avion, pause the movie" in one breath, or "Avion" and a command within 4 s (a silent "Avion · Listening…" glass cue meanwhile; inside that window a sentence is accepted from 0.7 s of speech, so two-word Hebrew commands like "פרק הבא" are heard: 14 of 16 instead of 5, and only whole commands count there, so room talk said after the name no longer acts: 0 of 40 instead of 7); room talk is ignored, and the Hebrew אווירון ("aviron") no longer wakes it. The Hebrew words come from the engine's own [`FormantSynthesizer`](../include/media/ai/FormantSynthesizer.hpp) (a Klatt-style phoneme synthesiser: no Hebrew voice is installed) and from French voices. `--voice microphone` turns it on in the demo (off by default). The templates come from synthetic voices only, and no real speaker has tested them. See [voice](voice.md).
- [`PcmConverter`](../include/media/audio/PcmConverter.hpp): channel remix and exact rational-phase band-limited resampling, so an audio track of another sample rate or layout (a 44.1 kHz dub, a 5.1 mix beside stereo) can be switched to while playing, spliced sample-exactly, without reopening the endpoint. See [tracks](tracks.md).
- [`PlaybackCoordinator`](../include/media/engine/PlaybackCoordinator.hpp) and [`media_player_demo`](../apps/media_player_demo.cpp): connected file-to-screen/audio playback, hardware-clock pacing and allocation probes.

The playable subset is progressive 8-bit H.264 with B-pictures (pyramids, MMCO, long-term references, list modification), and HEVC Main/Main10 up to 3840×2160 with B-pictures, each with optional AAC-LC mono/stereo/5.1 at any sample rate (Windows resamples when the endpoint runs at another rate). MP4 files may carry a single rate-1 edit list. PQ/HLG HDR is tone-mapped to the SDR output, with each picture's own peak detected before it is converted, smoothed in presentation time, and restarted on every seek and scene cut ([HDR peak per epoch](picture.md#hdr-peak-per-epoch-2026-10-16): a seek's landing is bit-identical to the same picture decoded cold). Since SDK API 17 (2026-11-05) Matroska and WebM play too, AV1 plays through Windows' own software decoder (the GPU here has no AV1 decoding; [docs/matroska.md](matroska.md)), and Opus mono/stereo through Windows' decoder. H.264 interlacing and custom scaling matrices, multi-entry edit lists, VP9, seeking in fragmented MP4, reconfiguration, and Linux/Apple endpoints remain outside this milestone. See the layer documents for exact admission limits. This is an initial playback engine, not general MP4 compatibility.

## Lifetime contract

1. Initialize an arena on its single owner thread, then `Create<SpscRingBuffer<MediaPacket, 256>>()` and allocate fixed payload blocks. Check every result.
2. Create resource tables and workers during setup. `Seal()` the arena before streaming. A sealed arena rejects all further sub-allocation; queues recycle their existing slots.
3. The producer writes a whole descriptor through `AcquireWriteSlot()`, then calls `CommitWriteSlot()`. Null means full. Repeated checkout returns the same outstanding slot. Cancellation invalidates the producer pointer without publishing.
4. The consumer reads through `PeekReadSlot()`, then calls `ReleaseReadSlot()`. Null means empty. A peek holds the slot until release. Commit/release without checkout return false.
5. Stop using slot pointers after commit, cancellation, or release. Payload blocks and GPU surfaces have separate lifetimes; releasing a descriptor never implies GPU completion.
6. Stop/join all workers and retire outstanding resource uses before arena destruction, `Shutdown()` or `Reset()`. `Reset()` rewinds an arena to empty and unseals it, keeping its capacity and committed pages, for the next file of a session; it is never a live operation. Reinitialize only after shutdown.

Each endpoint belongs to exactly one thread. Arena statistics and lifecycle operations are not concurrent telemetry APIs. Neither component owns worker threads or enforces a playback state machine for its caller.

`Create` uses `std::construct_at`, the standard placement construction operation; it does not allocate storage. Its objects must be nothrow constructible and trivially destructible. Arbitrary user constructors must themselves respect the caller's allocation policy. Large queues belong in the arena, not on a thread stack.
